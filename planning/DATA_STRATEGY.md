## Common dictionary and quality rules

Every field dictionary must state: name, business meaning, source, type, allowed values, unit, null policy, example, whether additive, and key/relationship role. Every table must state grain, primary key, foreign keys, date coverage, filters, and intended analysis. For simulation CSVs, IDs are strings, dates ISO `YYYY-MM-DD`, counts integers, amounts decimal NPR with two places. External dictionaries record observed IDs/types/date encodings, source units/currency and any explicit preparation conversions; preserve originals. Use integer paisa internally during simulation generation to avoid inconsistent rounded totals, then serialize NPR consistently. Define rounding at display only; comparison tolerances must be explicit.

- Preserve missing data as missing. Do not replace unknown dates or costs with zero. Null dates have field-specific meanings, below; unexpected missing amounts block release. Known zero activity is explicit zero.
- A zero denominator returns null/“N/A,” accompanied by numerator and denominator; no invented 0% rate or infinite efficiency. Show excluded unknown records and sensitivity when their absence could change the decision.
- Sum amounts/counts only across disjoint populations. Overall rates are `SUM(numerator) / SUM(denominator)`, not mean of subgroup percentages. Recalculate distinct counts at the displayed dimension; category-level distinct orders do not sum to company orders.
- Dictionary documents `Unknown` categories and whether they remain visible. A hidden unknown segment must never silently improve a metric.
- Prepared simulation month keys are first-of-month dates, not month names. Keep calendar order and fiscal choice explicit. 2025 alone supports month-to-month or within-year comparisons, not year-over-year growth. External sources retain audited frequency and coverage; missing years/periods and historical snapshots must remain visible.

## Retained simulation metric contracts

**Scope:** the five detailed contracts below define the proposed synthetic simulation. Their safeguards—grain, weighted rates, date populations, nulls, signs, boundaries and reconciliation—also govern external work, but formulas require source-specific support. For example, an audited source `Profit` field must not be relabeled gross profit or reconstructed into COGS without evidence; a discount rate is not a line discount amount; a return flag is not a refund amount or return event date. Establish source meanings before selecting compatible metrics.

### Retail: sales, orders, profits, and return timing

Scope: completed orders placed during 2025. `gross_sales_npr = quantity * unit_price_npr`; `sales_npr = gross_sales_npr - discount_npr`; `gross_profit_npr = sales_npr - cogs_npr`. These are **pre-return merchandise** measures; exclude tax, freight, overhead, and currency conversion. Sales and gross profit are additive across lines. Orders = distinct `order_id`; customers = distinct `customer_id`. AOV = total sales / distinct orders; gross margin = total gross profit / total sales. Discount rate = total discount / total gross sales. All zero denominators return null.

Pilot AOV by channel/region/month uses order-level dimensions. Product-category order counts overlap and cannot be summed; category AOV must be labeled category sales per order containing that category. Growth = `(current month sales - prior month sales) / prior month sales`; January comparison unavailable without prior-year data. Customers are identified by fictional stable IDs; no causal claims about discount effects.

Advanced return view: sum refund events through cutoff for each 2025 order. `cohort_net_sales_npr = sales_npr - refunds_npr`; `cohort_net_cogs_npr = cogs_npr - recovered_cost_npr`; `cohort_gross_profit_npr = cohort_net_sales_npr - cohort_net_cogs_npr`. These restate the sale cohort using observed refunds and are **not period-recognized accounting revenue**. A November purchase refunded in December affects November's cohort measure and December's refund-event total. Never combine those as if they share a date basis. Return incidence = distinct sold orders with at least one return observed by cutoff / distinct sold orders. Unit return rate = returned units / sold units; refund rate = refunds / pre-return sales. December has shorter follow-up: compare equally mature cohorts or acknowledge censoring. Null return row after aggregation means no observed return only if source completeness is validated.

### Finance: comparable expense budgets and actuals

Scope: all 2025 expense postings and all matching budget cells; calendar month, department, and account. Aggregate postings first, then combine with unique budget cells. A raw transaction-to-budget join repeats budgets and is prohibited for totals. Beginner table must reconcile to original signed actual totals and original unique budget totals.

`variance_npr = actual_npr - budget_npr`; positive expense variance is unfavorable, negative favorable. `variance_pct = variance_npr / budget_npr` for positive budget; approved zero or missing budget yields null percentage with explicit label. Approved zero plus positive actual is “unbudgeted spend against zero,” not 0% variance; missing budget is “budget unknown” and variance amount also null. Actual absent from a known budget cell means zero postings only after completeness is validated. Total variance and its percentage use only the comparable known-budget population, with unknown-budget actual amounts separately reported; never silently treat unknown budgets as zero. Recalculate aggregate percentage from total actual and budget for that population. Credits reduce actual; inspect large reversals before concluding savings. Favorability refers to expense only; do not reuse that sign rule for revenue. Finance is a management-expense dataset, so no unsupported claim that it reconciles retail revenue or audited accounts.

### Operations: service reliability as of cutoff

Scope: noncanceled shipments dispatched by cutoff. Due population = shipments with valid promised date <= cutoff; it includes delivered and undelivered due shipments. On-time = delivered date <= promised date and delivered date <= cutoff. Rate = on-time due shipments / all due shipments. Undelivered overdue shipments remain denominator failures; delivered-after-cutoff values are invalid for this extract. Shipments due after cutoff do not enter service-rate denominator even if delivered early; show separately. Unknown promises are excluded from this rate with a visible exclusion count and block clean release if unexpected.

`lead_days = delivered_date - dispatch_date` for delivered shipments only, in calendar days. Show mean, median, distribution and sample size, labeled **completed shipments**; it does not describe unresolved shipment duration. `days_past_due_asof = max(cutoff - promised_date,0)` for pending due shipments; day-of-promise pending is a failure in the end-of-day cutoff service snapshot but zero days past due. Carrier/warehouse rates must be weighted by due shipments, and comparison must consider shipment mix and counts. Do not substitute distinct orders for shipment denominator when orders split.

### Marketing: funnel and attributed efficiency

Scope: paid campaign-days in 2025; conversion is a purchasing session under the simplified same-day funnel; no view-through, multi-touch, or cross-device inference. CTR = clicks / impressions; session conversion rate = conversions / sessions; CPC = spend / clicks; CPA = spend / conversions; attributed ROAS = attributed revenue / spend. Ratios use sums at every displayed scope. Zero denominator => null. Spend=0 with conversions is flagged for review; no infinite ROAS. Funnel counts use one consistent event definition and date basis, not unrelated users versus sessions.

Daily conversions reconcile the count of unique attributed orders under the one-order-per-purchasing-session assumption, and daily attributed revenue reconciles the sum of those unique order amounts, using pre-return sales; organic orders are outside this table. Revenue must not exceed scoped retail pre-return sales at company total after date alignment. The generator assigns each paid-attributed order to one campaign; the release does not contain touchpoint history and cannot validate a last-click claim. This is a synthetic single-campaign allocation for teaching. Attribution describes that chosen assignment rule, not incremental lift or causal campaign impact. High ROAS alone does not establish profit because COGS, returns, and overhead are excluded. Frequency/reach and unique customers are not inferred by summing daily impressions or sessions.

### HR: historical populations and fair comparisons

Scope: synthetic employment spells, monthly calendar cohorts; no real employees or protected-attribute inference. Exit date is first inactive date. For month `[start,next_start)`: opening headcount = hires before start with exit null or exit >= start; closing = hires before next_start with exit null or exit >= next_start. Hires = hire dates in month; exits = exit dates in month. Company bridge: `closing = opening + hires - exits`. This convention counts a hire on month start in hires, and an exit on month start in exits; both reconcile to the previous day's opening stock. Employee active on a date `d` means hire <= d and exit null or exit > d.

Monthly average headcount = `(opening + closing) / 2` (an approximation, named as such). Monthly turnover = exits / monthly average headcount; null if denominator zero. Annual turnover = annual exits / average of the 12 monthly average headcounts, not sum/mean of monthly turnover and not December/current headcount. Department bridge adds transfers in minus transfers out; hire department uses hire date, exit department uses last active day, and transfer counts use effective date. Define and validate same-day changes before generating them. Initial release should avoid an exit and transfer on the same day to keep this extension teachable.

Tenure at cutoff includes only active employees, elapsed days from hire to cutoff; departed tenure is a separate distribution to exit date. Display days, or label approximate years if dividing days by 365.25. Recruitment time-to-fill = offer accepted date - opened date for accepted requisitions; time-to-start = hire date - opened date for started hires. Pending requisitions remain visible as open age = cutoff - opened date; never set pending durations to zero or silently exclude them from discussion. Compare departments with counts, job-family mix, and time exposure; small groups must be combined or flagged as unstable. Minimum comparison count is a recommended teaching threshold of 5, to be reviewed, not a privacy guarantee or statistical rule.
